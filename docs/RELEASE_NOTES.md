# 버전 안내 — 1.5.0

- `analyze` 보고서를 GigE Vision 진단 중심으로 재구성했습니다. **종합 판정 → 주요 문제와 권장 조치 → 카메라 NIC 체크리스트 → 카메라·SDK 세션 → 상관 타임라인** 순서로 표시하고, 기존 전체 표는 접힌 부록으로 옮겼습니다.
- 활성 하드웨어 NIC를 카메라 NIC·사내망 NIC로 판별합니다(GigE 필터 드라이버, `--expected-camera-ip` 서브넷, `--camera-mac` Neighbor 캐시, SDK 로그 MTU, Jumbo, 게이트웨이). 연결되지 않은 NIC·가상 NIC·장치 없는 NIC는 본문에서 숨기고 부록에만 표시합니다.
- 규칙 기반 판정: 링크 속도, Jumbo Packet·IP MTU, Receive Buffers, Interrupt Moderation, EEE/Green Ethernet, 전원 관리, 벤더 간 GigE 필터 중복, 보안·VPN·캡처 필터, IP/게이트웨이, 서브넷 중복, 방화벽 프로필, 수신 오류·폐기 카운터, 링크 분리 이력, SDK 패킷/이미지 손실·timeout·패킷 크기와 NIC MTU, SDK 모듈 앱 오류, 링크 분리와 SDK/앱 오류의 시간 상관. 각 문제에 관찰값·기대값·권장 조치·근거와 `확인`/`추정` 구분을 표시합니다. 값이 없으면 `판단 불가`이며 비활성으로 판정하지 않습니다.
- 분석 결과 폴더에 `findings.json`(전체 판정)과 `llm-context.json`(컴퓨터명·사용자명·카메라 시리얼·MAC 하위 3바이트·공인 IPv4를 마스킹한 요약)을 추가로 생성합니다.
- `analyze --ai-review <file>`로 외부에서 만든 LLM 의견(스키마 버전 1)을 검증해 "AI 심층 의견 (LLM 생성 · 검증 필요)" 절로 넣습니다. EXE는 계속 네트워크에 접근하지 않습니다. LLM 호출은 배포물에 포함되지 않는 엔지니어용 `tools/ai-review.ps1`(Codex CLI, ChatGPT 로그인)이 사용자 확인 후 마스킹된 컨텍스트만 보내는 별도 단계입니다.
- `문제 항목만 보기` 필터를 추가하고, 미확인 필터 배지의 깨진 문자열을 수정했습니다.
- 수집 기능과 snapshot/manifest 스키마 1은 변경하지 않았습니다. 기존 결과 ZIP도 다시 수집 없이 새 보고서로 분석할 수 있습니다. Sapera `Logs.dat` 내용은 판정에 사용하지 않습니다. 판정 기준값은 합성 자료로 시험했으며 실제 카메라 PC 자료로 계속 조정합니다.

## 이전 1.4.0 변경

- 실행 사용자 프로필의 `MVSDK\<Application 이름>\*.log`를 기본 수집에 추가합니다. 최근 수정된 로그부터 192개·합계 64 MiB, 파일마다 마지막 16 MiB를 원본 바이트로 보존합니다. `mvsdk-index.json`과 snapshot에 앱·원본 경로·시각·복사 범위·실패·누락을 기록합니다. 자동·명시 로그를 같은 SDK 분석기로 처리하고, ZIP/폴더 입력 모두 스트리밍으로 해시 검증 및 오프라인 분석합니다. 파일 날짜 필터·중첩 폴더·ZIP/덤프 수집·SDK 실행은 없습니다.

- Sapera Log Server 로그를 기본 수집에 추가합니다. 레지스트리 `LogFile`(64비트/32비트 순서), 값이 없으면 `%WINDIR%\System32\Logs.dat`를 사용합니다. 64 MiB 이하 전체 원본을 `sapera-Logs.dat`로 저장하고 manifest 해시와 ZIP CRC로 검증합니다. 초과 파일은 자르지 않으며 파일 없음·권한·잠금·수집 중 변경을 기록합니다. 서비스/설정 변경이나 텍스트 파싱·날짜 필터는 없습니다.

- 카메라/SDK 관련 Application Error 1000, Application Hang 1002, WER 1001, .NET Runtime 1026을 XML의 앱·모듈·경로로 선별합니다. 반복 가능한 `--app-name`으로 추가 앱을 지정합니다. Huaray 설치 목록은 DisplayName과 Publisher에서 인식합니다.
- `mvGenICamForEthernet`을 전용 System 증거 파일과 수집 작업으로 분리합니다. 일반 System의 선택 예산을 차지하지 않으며 전체 Windows/SetupAPI 100,000행 제한을 유지합니다.
- 자동 수집 로그와 명시한 `--log-file`의 MVSDK/CamClient 로그에서 세션·버전·카메라·MTU/패킷·타임아웃·통계·오류 유형을 추출합니다. SDK 이벤트와 요약도 manifest에 해시로 등록합니다. 기존 원본 로그 번들은 스트리밍 분석을 지원합니다.
- 수집/분석의 `--log-utc-offset`으로만 SDK 시각을 UTC로 해석합니다. 분석 값이 우선하며 미확정 시각은 원문 표시와 날짜 추출 제외 횟수로 남깁니다. `kind: sdk`는 Windows 이벤트 건수와 별도입니다.
- 애플리케이션 사고, SDK 세션, 덤프 메타데이터, 물리 메모리 표를 추가합니다. 알 수 없는 NDIS 링크 속도는 미확인으로 표시하며 64비트 메모리 용량을 보존합니다.
- `--dump-file`은 기존 덤프 메타데이터만 읽습니다. 예외 스트림이 없으면 예외 정보 없음으로 표시합니다. `--attach-dumps`는 별도 원본 ZIP·체크섬을 만들고 기본 manifest에 참조합니다. 기본 ZIP 크기 제한은 늘리지 않습니다.
- `--include-evtx`는 선택한 System/Application Record ID의 원본 EVTX 복사본을 추가합니다. 선택 출력 실패·시간/크기 제한은 기본 자료를 유지하며 부분 수집으로 표시합니다.
- 버전은 1.4.0, snapshot/manifest 스키마는 1을 유지합니다. 기존 CLI와 번들을 지원하며 외부 프로그램의 ZIP 가져오기 기능은 포함하지 않습니다.

## 이전 1.3.1 변경

- 필터 활성값·NIC 고급 설정 키의 비어 있거나 불명확한 값을 처리합니다. 나머지 보고서를 생성하며 미확인 값을 비활성으로 간주하지 않습니다.
- 동일 설명의 NIC가 여러 개면 링크 이벤트를 마지막 NIC로 연결하지 않고 모호한 후보를 표시합니다.
- 사용자 로그 최대 16개 × 16 MiB를 작은 단위로 읽어 SHA-256과 ZIP CRC를 검증합니다. 본문을 분석 메모리에 보관하지 않습니다. 나머지 증거 파일은 기존의 파일당 64 MiB·전체 256 MiB 제한을 유지합니다. 사용자 로그에는 별도로 최대 256 MiB 제한을 적용합니다.
- SetupAPI 선택 구간을 최대 20,000개로 제한하고 제한 도달을 부분 수집으로 표시합니다. 이벤트 8개 채널의 최대 80,000개와 합쳐 분석기의 100,000행 제한에 맞춥니다.
- Windows 파일 속성에 제품명·버전 정보를 추가했습니다. 표시된 제품 식별 정보는 코드 서명을 대신하지 않습니다.
- 배포용 사용 안내와 내부 검증 기록을 분리했습니다. 고객 원본 자료와 내부 검증 기록은 배포하지 않습니다.

기능 시험은 설정 변경 없이 합성 자료로 오류 조건과 원본 보존을 확인합니다. 실행 파일의 서명 상태와 별도 환경 검증 기록 제공 여부는 패키지의 `RELEASE_STATUS.json`을 확인합니다. 시험하지 않은 장비의 호환성이나 카메라 운용 중 무영향을 보장하지 않습니다.
