- MSVC 19.44, Windows SDK 10.0.26100.0, CMake 3.26.3으로 x64 Release 빌드 성공. `/MT` 정적 런타임으로 고객 설치 의존성 제거.

- 현재 환경의 NDIS 인터페이스 133개(필터 인터페이스 108개 포함)를 수집. 최종 어댑터 직렬화도 실제 API로 확인.
- 접근 가능한 NIC/IP 정책·영구 경로·고급 설정·방화벽·감사·TCP/IP 레지스트리를 수집 전후 비교하여 동일함을 확인. 접근 불가 항목은 검증된 것으로 간주하지 않음.
- 제품 EXE는 일반 사용자 실행 시 종료 코드 3을 반환하며 결과 폴더를 생성하지 않음.
- 독립 Python ZIP 라이브러리로 CRC, manifest의 전체 파일 크기·SHA-256, 스키마, 3,502개 타임라인 증거 연결과 3,468개 원본 이벤트 XML의 Provider/Event ID/Record ID/시각 일치 확인.
- UTC/지역 시각 일치를 별도 날짜 라이브러리로 검증. 100 ns 단위 원본을 밀리초로 표시할 때 시간대가 1분 어긋나지 않도록 회귀 시험 추가.
- 첫 번째 타임아웃 증거 시험 ZIP도 CRC·파일 해시·완전한 이벤트의 연결 검증 통과. 불완전한 마지막 행은 원본을 유지하고 보고서에서 누락 표시.
- 금지 API 정적 검사 통과. EXE의 네트워크 DLL 직접 호출은 숫자 주소 변환 함수이며 소켓 생성·접속·송신 함수가 없음. 배포 EXE는 Windows 시스템 DLL만 동적으로 의존함.

검증 스크립트는 `tools/verify_safety.py`, `tools/verify_bundle.py`, `tools/validate-readonly.ps1`이며 원시 결과는 Git에서 제외한 `build` 및 `test-results`에 보관됩니다.

## 남은 배포 전 환경 검증

- 사용자가 관리자 권한으로 실행한 기존 제품의 실제 결과 두 개는 확인했습니다. **최종 1.4.0 제품 EXE의 관리자 전체 수집 전후 설정 비교**는 아직 수행하지 않았습니다. 현재 개발 세션은 관리자 토큰이 아니며 UAC 요청이나 권한 변경을 수행하지 않습니다.
- Windows 10 x64, 별도 Windows 11 PC와 고객사 NIC 제조사·드라이버 조합.
- 현장과 동일한 카메라 운용 중 프레임 손실·연결 유지·CPU·메모리·디스크 부하 측정.
- 시험실의 프로세스·파일·레지스트리·네트워크 접근 추적을 통한 런타임 검증. 정적 API 검사와 설정 전후 비교를 완전한 런타임 무변경 증명으로 표현하지 않음.
- 배포 코드 서명. 인증서가 제공되지 않아 현재 EXE는 서명되지 않음.

이 미검증 조건 때문에 고객 PC 설정을 변경하거나 보안/감사 정책을 완화하는 우회 기능을 추가하지 않았습니다.

- 일반 권한의 실제 EXE 무인자 실행은 안내 후 종료 코드 3을 반환하며 EXE 폴더나 현재 폴더에 결과를 만들지 않는 것을 확인.

- 입력 폴더와 출력 경계 비교는 Windows의 대소문자 비구분 규칙을 적용. 원본 폴더 안에 보고서를 생성하는 우회는 거부.

## 1.1.1 — NIC Jumbo·절전 설정 표시

- 기존 advanced / power / registry의 읽기 전용 수집 결과를 이용해 Jumbo Packet과 IP MTU, 전원 차단 허용, Selective Suspend, 연결 해제 시 절전, Wake 설정, EEE 등 드라이버 고급 설정을 별도 HTML 표로 표시. 수집 질의와 조회 API는 변경하지 않음.
- NIC의 장치 GUID로 설정과 MTU를 연결. 분리된 NIC의 저장 레지스트리 값은 적용 상태를 추정하지 않고 원래 형식과 경로를 표시.
- 기능 시험에 GUID 매핑, 이름 변경·공통 드라이버 설명의 혼동 방지, Jumbo 선택 코드 보존, MTU 분리, 분리된 NIC 레지스트리 값, 전원관리 Unsupported/Disabled/Enabled/Inactive 구분 추가.

## 1.2.0 — NIC별 보고서 구성

- NIC별 IP 요약표와 상세 카드를 추가. IPv4 주소·서브넷 마스크·할당 방식, 게이트웨이·DNS·별도 IPv6, NIC 드라이버, 필터 활성/비활성, 전원·Jumbo·EEE·버퍼·RSS·오프로드 설정을 해당 NIC 안에 표시.
- 연결된 NIC 주소 요약을 먼저 표시하고 연결되지 않은 NIC 주소/구역은 접어서 표시. 검색·Up 필터·NIC 펼치기/접기·요약표에서 상세 카드 이동 지원.
- 설정과 필터는 GUID, GUID가 없는 프로필은 기록된 ifIndex로 연결. 드라이버 버전은 GUID와 PNPDeviceID/DeviceID로 연결. 상충하는 GUID를 이름/ifIndex로 대체하지 않는 시험과 NIC 간 정보 혼합 방지 시험 추가.
- 실제 VT_PC_THRP 자료에서 카드 45개, 기본으로 열린 하드웨어 카드 3개, Up 필터 시 카드 7개 확인. 이더넷 19의 IP/마스크, NIC 드라이버 12.18.11.1, Jumbo 표시값 9014바이트와 MTU 9000, EEE/전원 설정, 비활성 Matrox 필터를 확인. 전체 Filter 개수에는 QoS 같은 Windows 필터도 포함.
- Chromium에서 NIC/필터 검색, 검색 결과 없음, Up 필터와 복원, 펼치기/접기, 요약표 링크 이동 검증. 데스크톱 1440px 및 작은 화면 390px에서 표시 확인, 문서 전체 가로 넘침 없음, 인쇄 미디어에서 제어 버튼 숨김 확인. 콘솔 오류 없음. 브라우저별 PDF 페이지 배치는 별도 확인 대상.
- CTest 2개와 정적 읽기 전용 API 검사 통과. 기존 증거 파일 16개의 해시가 분석 전후 동일하며 System timeout은 보고서와 종료 코드 1에 유지.

## 1.3.0 — 특정 날짜의 이벤트 추출

- `analyze --date YYYY-MM-DD [--utc-offset ±HH:MM]` 추가. 기본 UTC+09:00이며 원래 UTC 시각으로 그날 시작 이상/다음 날 시작 미만을 선택. 분석 PC의 시간대나 원본 local 문자열로 날짜를 추정하지 않음.
- 날짜를 지정할 때 HTML에 선택 범위·원본/선택 횟수·이벤트 목록을 표시하고 CSV 및 원래 JSON/XML을 담은 JSONL을 같은 새 결과 폴더에 생성. 일반 분석은 HTML 하나만 생성.
- 자정 전후(100 ns 형식 포함), 윤년/잘못된 날짜, 음수 offset, 시각 미상 SetupAPI 제외, 날짜에 기록 없음, 원래 XML·필드/행 번호 보존, 시간순 정렬, CSV 수식 방지, 중복 옵션과 날짜 없는 offset 거부 시험 통과. 원본의 partial/timeout 상태 유지.
- 실제 VT_PC_THRP의 2026-10-08 UTC+09:00 추출: 이벤트 366개 + SetupAPI 1개 = 총 367개. 별도 Python datetime 계산과 모든 원본 레코드·증거 행·CSV/JSONL 횟수가 일치하며 증거 파일 16개는 해시가 동일함.

## 1.3.1 — 배포 검토 사항 개선

- `Enabled=null`과 `RegistryKeyword=null` 입력에서도 HTML을 생성하며, 미확인 필터는 비활성과 구분해 집계하고 미해석 상태를 표시합니다. 고급 설정과 원래 null 값은 보존합니다. 문자열 조회값의 형식을 확인하는 공통 함수를 적용했습니다.
- 동일 설명의 NIC가 여러 개면 링크 이벤트를 특정 NIC로 확정하지 않고 모호한 후보를 표시합니다. 동일 설명 3개와 고유 설명 1개의 연결 조건을 회귀 시험으로 확인했습니다.
- 사용자 로그를 별도 16 × 16 MiB 예산으로 스트리밍 해시/CRC 검증하며 본문을 분석 모델 메모리에 보관하지 않습니다. 일반 증거의 64 MiB/256 MiB 제한은 유지합니다. manifest는 폴더와 ZIP 모두 1 MiB 제한입니다.
- SetupAPI 선택 구간은 최대 20,000개로 제한하여 현재 8개 이벤트 채널의 최대 80,000개와 합쳐 JSONL 100,000행 제한에 맞춥니다. 제한 도달은 partial로 기록합니다.
- Release 빌드와 CTest 3/3 통과. 별도 배포 회귀 시험은 정상 입력, null 설정 2종, 사용자 로그 256 MiB ZIP/폴더 입력, 스트리밍 로그의 잘못된 SHA/CRC를 검증했습니다. ZIP 및 폴더 입력 원본 보존도 확인했습니다.
- 최종 배포 EXE로 기존 고객 자료를 분석해 이벤트 7,739개와 NIC 카드 45개, 날짜 추출 이벤트 366개 + SetupAPI 1개를 확인했습니다. 추출된 367개 원래 레코드가 원본과 같고 원본 파일 16개의 해시가 동일합니다. 기존 System timeout과 종료 코드 1도 유지합니다.
- 금지 API 정적 검사 통과. FileVersion `1.3.1.0`, ProductVersion `1.3.1`, publisher 표시명 `FetchNetworkConfig` 확인. 표시명은 제품 식별용이며 인증된 회사 신원이 아닙니다.
- 사용자 지시에 따라 인증서 없이 패키징했습니다. 최종 EXE는 NotSigned이며 ZIP의 RELEASE_STATUS.json에 기록합니다. 서명을 요구하는 배포에는 별도 `-RequireSignature` 검사를 사용할 수 있습니다.
- 고객용 문서를 내부 README/VALIDATION과 분리했습니다. 패키지는 허용된 파일 목록, 실제 고객/개발자 식별 문자열 부재, CRC·해시·EXE 버전·서명 상태 검사를 통과했습니다. 내부 검토/환경 시험 문서와 고객 원본 자료는 포함하지 않습니다.
- 환경 검증 스크립트에 최종 제품 EXE 수집 전후 비교와 부모 프로세스 자원 표본 기록을 추가했습니다. PowerShell 구문 검사 통과. 현재 비관리자 세션에서 `-ProductCollection`은 자동 상승·수집·결과 폴더 생성 전에 거부되는 것을 확인했습니다. 관리자 정상 경로, Windows 10, 카메라 운용 중 부하 및 실제 접근 추적은 시험 장비에서 별도 수행해야 합니다.
- 환경 검증 기록을 제공하면 버전·최종 EXE 해시·필수 완료 항목을 확인하고, 지정하지 않으면 `environment_validation: pending`으로 남깁니다. 미실시 검증을 완료로 표시하지 않습니다.
