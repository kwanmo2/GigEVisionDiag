# 읽기 전용 수집 계약

## 허용되는 동작

- Sapera Log Server의 `LogFile` 레지스트리 값을 읽고, 값이 없으면 `%WINDIR%\System32\Logs.dat`를 읽기 전용으로 열어 최대 64 MiB 전체를 결과 폴더에 복사. 서비스나 Log Viewer를 실행·중지하지 않고 원본 바이트 및 읽기 전후 메타데이터를 보존. 초과 파일은 미수집으로 기록하며 임의로 잘라 저장하지 않음.

- 실행 토큰의 사용자 프로필 내 `MVSDK`의 직접 하위 애플리케이션 폴더에서 기존 `*.log`만 조회. 최대 8,192개 항목을 탐색하고 최근 수정된 로그부터 192개·합계 64 MiB, 파일마다 마지막 16 MiB를 읽기 복사. 합계 잔여 예산에 맞춰 복사 범위를 제한하고 원본 앱·경로·시각·크기·오프셋·잘림·변경·실패·누락을 기록. 원본 설정·SDK·서비스를 변경하거나 로드하지 않고 중첩 폴더 및 junction/symlink를 따라가지 않음. `--days` 파일 필터는 적용하지 않음. 자동·명시 SDK 로그의 구조화 한도는 전체에 공동 적용.

- Windows 10/11 x64의 로컬 조회: IP Helper `Get*` 표, SetupAPI 장치 열거·속성 조회, 제한된 로컬 WMI `SELECT` 질의, `KEY_READ` 레지스트리, INetFwPolicy2의 `get_*`, Event Log `EvtQuery`/`EvtNext`/`EvtRender`.
- 현재 사용자 토큰의 관리자 여부 확인과 수집 프로세스 내부 COM 초기화.
- 기본적으로 EXE 옆, 또는 `--output`으로 지정한 기존 로컬/외장 폴더 안의 고유 결과 폴더 생성. 평면 결과 파일 이름만 허용하며 `CREATE_NEW`로 생성.
- 새 결과 폴더를 쓰기 경계로 사용. 폴더 핸들은 삭제·이름 변경 공유를 허용하지 않으며 junction, symlink, 원격 경로, 장치 이름, 경로 이탈과 대체 스트림을 거부.
- 사용자가 명시한 기존 로그와 `%WINDIR%\INF\setupapi.dev.log`를 읽기 핸들로 열기. 운용 프로그램과 공유 읽기·쓰기를 허용하고 원본 바이트와 메타데이터를 보존.
- 동일 EXE의 고정 수집 작업을 자식 프로세스로 실행. 상속 핸들은 입력·출력 파이프만 허용. 이름 없는 Job Object로 메모리와 수명을 제한하며 시간 초과 시 직접 만든 자식만 종료.
- `analyze` 명령은 관리자 권한 없이 저장된 로컬 결과 폴더/ZIP만 읽음. manifest 파일 해시와 ZIP CRC 검증 후 새 폴더에 `analysis.html`, `findings.json`(규칙 기반 판정), `llm-context.json`(마스킹된 요약) 생성. `--ai-review`로 지정한 로컬 JSON은 스키마 검증 후 보고서에 escape하여 삽입만 함. EXE는 LLM을 포함한 어떤 외부 서비스에도 접속하지 않음. 외부 LLM 검토는 배포물에 포함되지 않는 엔지니어용 `tools/ai-review.ps1`이 사용자 확인 후 마스킹된 `llm-context.json`만 Codex CLI로 전송하는 별도 단계임. `--date` 지정 시 해당 날짜의 `selected-events.csv` / `selected-events.jsonl`도 같은 폴더에 생성. 폴더 입력은 원본 폴더 밖에 결과를 저장하며, ZIP은 메모리에서 처리하고 원본 파일을 변경하지 않음.
- XML 분석은 메모리 스트림만 사용하며 DTD와 외부 resolver를 차단. HTML은 증거 문자열을 escape하고 외부 리소스·전송을 요청하지 않음. 사용자가 명시적으로 참고 링크를 누르는 것은 브라우저의 동작.
- 선택 옵션의 `EvtExportLog`는 JSONL로 선택한 Record ID만 새 결과 파일로 복사. 이벤트 삭제나 export-and-clear는 사용하지 않으며 내보낸 ID를 대조한 파일만 manifest에 등록.
- 명시한 기존 DMP를 읽기 핸들로 열어 헤더·시스템·모듈·예외 스트림의 제한된 메타데이터를 읽음. 프로세스 열기·덤프 생성·메모리/스택 실행 분석은 없음. 선택 첨부는 원본을 별도 ZIP으로 읽기 복사하고 읽기 전후 크기·수정 시각을 대조.
- 기본 ZIP은 모듈이 등록한 증거와 고정 보고서만 포함. 원본 덤프, 별도 첨부 ZIP, 미완성 선택 출력은 폴더에 존재한다는 이유로 포함하지 않음.

## 구현에 포함하지 않는 동작

- 레지스트리 쓰기, WMI 메서드 호출·인스턴스 변경, NIC/IP/경로/방화벽/전원 정책 변경.
- NIC 활성화·비활성화·재시작, DHCP release/renew, DNS·ARP 캐시 초기화.
- 서비스나 드라이버 설치·시작·중지, 예약 작업, 자동 시작, 상주 에이전트.
- 감사/SACL/로그 설정 변경, 이벤트 삭제·회전, 복원 지점·VSS 생성.
- 소켓 생성, 카메라 Discovery·접속·ForceIP·제어권 획득·SDK 로드, DNS/AD/원격 WMI, 인터넷 질의·업로드·업데이트.
- ETW/pktmon/netsh trace, 패킷 캡처, promiscuous mode, Npcap 설치.
- `Win32_Product`/MSI 상품 열거, 설치 복구·설정 도구 실행, PowerShell·cmd 등 외부 명령 실행.
- 결과 폴더 외부에 로그·임시 파일·캐시를 쓰거나 `%TEMP%`로 우회 저장.
- ACL/소유권/고객 실행 정책 변경 또는 권한 자동 상승.

## 보장 범위

이 계약은 **프로그램이 수행하는 설정 변경과 의도적인 파일 쓰기**에 대한 제한입니다. Windows, 보안 제품, COM/WMI 제공자가 자체 기록을 남길 수 있습니다. OS 실행 흔적 삭제는 수행하지 않습니다. 읽기 요청도 CPU·메모리·디스크 자원을 사용하므로 카메라 운용 중 영향은 시험 장비에서 측정합니다.

운용 중 로그나 DHCP 상태가 자연적으로 변하면 수집 과정에 차이가 생길 수 있습니다. 프로그램은 변화의 원인을 자기 동작으로 단정하거나 이를 되돌리지 않습니다. 결과에는 모듈 관찰 시각, 원본 로그 읽기 전후 시각·크기, 누락·시간 초과를 남깁니다.

타임아웃으로 프로세스가 중단되면 이미 기록한 증거 파일은 유지합니다. JSONL 마지막 행이 불완전하면 보고서에서 그 행을 제외하고 원본 파일과 누락 사유를 남깁니다. 설정의 자동 수정 기능과 그 명령행 옵션은 존재하지 않습니다.

## 배포 전 검증

1. `ctest` 기능 시험과 소스 금지 API 검사.
2. `tools/validate-readonly.ps1`로 NIC/IP 정책·고급 설정·전원·방화벽·감사·TCP/IP 레지스트리 전후 비교. 실제 API의 현재 권한 접근 결과 확인.
3. 관리자 권한의 Windows 10/11 시험 PC에서 제품 EXE 수집과 접근 제한·비활성 채널 확인.
4. 시험실에서 준비된 파일/레지스트리 접근 추적과 프로세스·네트워크 관찰로 의도적인 외부 쓰기·전송 부재 확인. 추적 도구는 고객용 수집기에 포함하지 않음.
5. 시험용 카메라 운용 중 CPU·메모리·프레임 통계 확인. 시간상 일치하는 장애와 인과관계를 구분.

정적 검사와 전후 비교만으로 모든 제공자·보안 제품의 내부 동작을 증명할 수는 없습니다. 시험하지 못한 운영체제·관리자 환경·카메라 운용 조건은 검증 기록에 명시합니다.
